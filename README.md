# MBA Mini-LMS

Веб-приложение для менеджера MBA-программы и её студентов: группы и архив, студенты, преподаватели, дисциплины, учебные периоды, расписание, оценки 0–100 с публикацией и историей изменений (видна только менеджеру), опросы (оценка преподавания и сервисные), уведомления в кабинете, выгрузки в Excel (.xlsx). Интерфейс на русском (по умолчанию) и английском.

| Часть | Технологии |
|---|---|
| Backend | .NET 10 (SDK 10.0.302, `global.json`), ASP.NET Core Web API, ASP.NET Core Identity, EF Core 10 + Npgsql, ClosedXML |
| БД | PostgreSQL 17 |
| Frontend | React 19, TypeScript 6, Vite 8, i18next, React Router 7 |
| Тесты | xUnit + WebApplicationFactory + Testcontainers (PostgreSQL); Vitest + React Testing Library |

Структура:

```
backend/src/MbaLms.Api          API (Domain, Data, Infrastructure, Controllers)
backend/tests/MbaLms.Api.Tests  интеграционные и unit-тесты
frontend/                       SPA (React + Vite), nginx-конфиг для Docker
docker-compose.yml              db + api + web
```

## Модуль менеджера: программа, группы, студенты, преподаватели, дисциплины

- **Программа одна.** Она создаётся при первом запуске (`Seed:ProgramName`, по умолчанию `MBA`). Менеджер может только переименовать её: карточка «Программа» на странице «Группы», `GET`/`PUT /api/manager/program`. Создать вторую программу или удалить существующую нельзя ни через API, ни в БД (уникальный индекс).
- **Группы.** Создание, редактирование, архивирование и возврат из архива, вкладки «Активные / Архив / Все». Архивирование меняет только статус: студенты, расписание, оценки, опросы и ответы сохраняются и видны менеджеру во всех разделах (фильтры по группе включают архивные). В архивной группе нельзя добавлять студентов, занятия, оценки и опросы; её студенты видят свою историю, но не отвечают на опросы. Удалить можно только пустую группу.
- **Студенты.** Менеджер задаёт ФИО, email, пароль и группу. Перевести студента можно в любую активную группу, перевод в архивную запрещён. История переводов не ведётся. Студента с оценками или ответами на опросы удалить нельзя.
- **Преподаватели и дисциплины.** Создание, редактирование и удаление неиспользуемых записей; используемые в расписании, оценках или опросах не удаляются.
- **Валидация на сервере.** Ошибки возвращаются с кодом по полю (`errors: { "name": ["duplicate"] }`), интерфейс показывает их под полем на текущем языке. Названия групп и дисциплин уникальны без учёта регистра, email студента уникален.
- **Поиск и пагинация.** Студенты ищутся на сервере по ФИО и email (каждое слово, без учёта регистра) с пагинацией: `GET /api/manager/students?search=&page=1&pageSize=25`, `pageSize` до 200. Выгрузка студентов учитывает тот же поиск. Группы, преподаватели, дисциплины и периоды исчисляются десятками, поэтому их ищут и листают в браузере, а API отдаёт полный список (он же служит источником выпадающих списков).
- **Подтверждения.** Архивирование, удаление группы, студента и записей справочников выполняются только после диалога с названием записи и описанием последствий.

## Расписание

- **Ручной ввод менеджером** (`/api/manager/lessons`): группа, дисциплина, преподаватель, дата, время начала и окончания, формат (очно / онлайн / гибрид), место или ссылка, комментарий, статус. Создание, просмотр, редактирование, удаление (с подтверждением). Занятия архивной группы видны, но не меняются.
- **Статус занятия:** «Запланировано» или «Отменено». Отменённое занятие остаётся в расписании студентов с пометкой и не считается ближайшим занятием на главной. Удаление убирает занятие совсем. Группа получает уведомление при создании, изменении, отмене и удалении.
- **Проверка времени на сервере:** окончание строго позже начала (`end_before_start`), занятие начинается и заканчивается в один день (`not_same_day`), в фильтре «с … по» дата окончания не раньше начала. Дополнительно это обеспечивает ограничение БД `CK_Lessons_EndsAfterStart`.
- **Пересечения** у той же группы или того же преподавателя (`GET /api/manager/lessons/overlaps`) показываются в форме как предупреждение. Сохранение не блокируется, данные автоматически не меняются; отменённые занятия не учитываются.
- **Студент** видит только расписание своей группы: группа берётся из профиля в сессии, параметры запроса вроде `groupId` игнорируются.
- **Выгрузка .xlsx** (`GET /api/manager/exports/schedule?groupId=&from=&to=&lang=ru|en`), только для менеджера. Это настоящая книга Excel (OOXML, ClosedXML, лицензия MIT), не CSV. Заголовки на русском или английском; дата — ячейка даты, начало и окончание — ячейки времени с часовым поясом в заголовке («Начало (Europe/Moscow)»); кириллица хранится как есть (UTF-8 внутри XML). Текст, похожий на формулу, записывается как текст.

## Оценки

- **Только менеджер** создаёт, меняет, публикует, снимает с публикации и удаляет оценки (`/api/manager/grades`, политика Manager на сервере). Значение — целое число от 0 до 100 включительно. Значения вне диапазона отклоняются с кодом `range`, дробные и пустые — как некорректный JSON (400). Перевода в буквы и GPA нет.
- **Одна оценка** на студента, дисциплину и учебный период: уникальный индекс в БД, повторное создание даёт 409 `duplicate`.
- **Ведомость** (`/manager/gradebook`, API `GET|PUT /api/manager/grades/sheet/{groupId}/{disciplineId}/{periodId}`). Менеджер выбирает группу, дисциплину и период и видит всех текущих студентов группы. Он вводит оценки сразу нескольким студентам и сохраняет их одним запросом. Отправляются только изменённые строки, новые оценки создаются черновиками. Студент другой группы или повтор студента в запросе отклоняется. Ничего не сохраняется, пока ошибочна хотя бы одна строка. Ведомость архивной группы доступна только для чтения. Кнопка «Опубликовать черновики» публикует черновики ведомости после подтверждения.
- **Draft / Published.** Студент видит только свои опубликованные оценки, на странице оценок и на главной. Черновики и чужие оценки ему недоступны. Параметры запроса вроде `studentId` игнорируются, студент определяется по сессии.
- **Уведомления** студент получает при первой публикации, при повторной публикации и при изменении уже опубликованной оценки. Изменения черновика и сохранение того же значения уведомлений не создают.
- **Изменение опубликованной оценки** требует явного подтверждения. В интерфейсе это диалог со списком «студент: старое → новое значение», в API флаг `confirmPublishedChange` (одна оценка) или `confirmPublishedChanges` (ведомость). Без флага сервер отвечает 409 `published_change_not_confirmed` и ничего не меняет.
- **Аудит** (`GET /api/manager/grades/{id}/history`, только менеджер). В каждой записи хранятся действие, старое и новое значение, старый и новый статус, кто изменил (email менеджера) и когда. Других данных, в том числе паролей, хешей и токенов, в истории нет. Записи остаются и после удаления черновика.

## Опросы

- **Два типа.** «Оценка преподавания» (TeachingEvaluation) требует преподавателя и дисциплину (`teacherId`, `disciplineId`: `required`). «Сервисный опрос» (ServiceSurvey) с ними не связан: присланные значения не сохраняются.
- **Жизненный цикл.** Менеджер создаёт и редактирует черновик: тип, название, описание, группа, период доступности «с … по» (время в часовом поясе приложения), вопросы. Затем публикует его (`POST /api/manager/surveys/{id}/open`), закрывает (`/close`) и при необходимости открывает снова. Вопросы меняются только у черновика. Удалить можно только черновик без ответов. Опрос с уже истёкшим периодом опубликовать нельзя (`survey_window_ended`). Все переходы подтверждаются в интерфейсе.
- **Вопросы.** Шкала с целыми границами от -100 до 100 (минимум меньше максимума) и необязательными подписями границ, до 100 символов. Выбор одного варианта (от 2 до 20 вариантов). Свободный текст (до 4000 символов). Любой вопрос можно сделать обязательным.
- **Приём ответа** (`POST /api/student/surveys/{id}/responses`). Ответ принимается, только если одновременно выполнены условия:
  - опрос опубликован и открыт;
  - текущий момент внутри периода доступности;
  - студент состоит в целевой группе, и она не в архиве;
  - студент ещё не отвечал.

  Сервер проверяет обязательность, диапазон шкалы, принадлежность вопроса и варианта этому опросу, отсутствие повторов вопроса и вид значения: для шкалы — только `intValue`, для выбора — только `optionId`, для текста — только `textValue`. Ошибки возвращаются по каждому вопросу.
- **Один ответ на опрос от студента.** Лимит проверяется перед записью и закреплён уникальным индексом `(SurveyId, StudentId)`. Повторная или одновременная отправка получает 409 `survey_already_submitted`. Изменить отправленный ответ нельзя.
- **Не анонимно.** Ответ связан со студентом из сессии, `studentId` из запроса не принимается. Менеджер видит автора, группу, время и все ответы, а также сколько студентов группы ответило. Студент видит только свой статус прохождения и собственные ответы. Чужие ответы, сводки, счётчики ответов и результаты ему не отдаются: проверяется по сырому JSON студенческих endpoint.
- **Уведомление** получают все студенты группы при первой публикации. Повторное открытие уведомлений не создаёт.
- **Выгрузка .xlsx** (`GET /api/manager/exports/surveys/{id}?lang=ru|en`), только для менеджера. Одна строка на ответ: студент, группа, время отправки, затем по столбцу на вопрос. Значение шкалы — числовая ячейка, выбор и текст — текстовые ячейки.   Текст, начинающийся с `=`, `+`, `-`, `@`, табуляции или возврата каретки, записывается как литерал с префиксом-апострофом, а не как формула. Так же обрабатываются заголовки.

## Уведомления

- **Только в кабинете.** Email, SMS и мессенджеры не подключены.
- **События:**
  - публикация опроса для группы;
  - создание, изменение, отмена и удаление занятия группы;
  - перенос занятия в другую группу: старая группа получает «удалено», новая — «добавлено»;
  - первая публикация оценки и изменение уже опубликованной оценки.
- **Без лишних уведомлений.** Сохранение формы без изменений, правка черновика оценки и повторное открытие опроса уведомлений не создают.
- **Получатель и данные.** Каждое уведомление привязано к одному пользователю, имеет время создания и время прочтения (пусто, пока не прочитано). Запись создаётся в той же транзакции, что и само изменение.
- **Только параметры, без текста.** В БД хранятся тип и параметры события (название дисциплины, дата, вид изменения). Сама оценка в уведомление не попадает. Текст собирается в интерфейсе на текущем языке, поэтому после переключения языка старые уведомления тоже показываются на новом языке.
- **Доступ только к своим.** `GET /api/notifications`, `GET /api/notifications/unread-count`, `POST /api/notifications/{id}/read` и `POST /api/notifications/read-all` работают только с уведомлениями пользователя из сессии. Чужое уведомление даёт 404, в том числе для менеджера. Без входа — 401.
- **Счётчик непрочитанных** в шапке обновляется сразу после отметки о прочтении.

## Языки интерфейса

- **Русский по умолчанию, английский по выбору.** Переключатель есть на странице входа и в шапке. Выбор хранится в `localStorage` этого браузера (`mbalms.lang`). Неизвестное значение там сбрасывается на русский. Атрибут `lang` у `<html>` меняется вместе с языком.
- **Все строки интерфейса** лежат в `frontend/src/i18n/ru.ts` и `en.ts` с одинаковым набором ключей. Даты и числа форматируются по выбранному языку (`ru-RU` / `en-GB`). Формат встроенного в браузер поля даты (`<input type="date">`) задаёт сам браузер по своему языку.
- **Ошибки и валидация.** Сервер возвращает коды ошибок (`code`) и коды полей (`errors`), а не тексты. Интерфейс переводит их на текущий язык. Стандартные сообщения ASP.NET о неверном формате значения приходят как код `invalid`.
- **Данные не переводятся.** Имена, названия, комментарии и ответы показываются так, как их ввели.

## Требования

- Docker Desktop (или Docker Engine + Compose v2) — для запуска в Docker и для тестов backend.
- Для режима разработки дополнительно: .NET SDK 10.0.302+ и Node.js 24 LTS (npm 11).

## Запуск в Docker (всё целиком)

```powershell
copy .env.example .env      # Linux/macOS: cp .env.example .env
```

Отредактируйте `.env`:

- `POSTGRES_PASSWORD` — надёжный пароль БД (без символа `;`).
- `MANAGER_EMAIL` / `MANAGER_PASSWORD` — учётная запись менеджера, создаётся при первом старте (пароль от 8 символов, с заглавной, строчной буквой и цифрой). Если пароль не задан, менеджер не создаётся, в логе API будет предупреждение.

```powershell
docker compose up -d --build
```

Откройте http://localhost:8080 (порт меняется переменной `WEB_PORT`). Миграции БД применяются автоматически при старте API.

После первого входа значение `MANAGER_PASSWORD` можно удалить из `.env`: учётная запись уже создана, повторный старт её не меняет. Сменить пароль можно в кабинете («Профиль»).

Студентов создаёт менеджер (раздел «Студенты»): он задаёт email и пароль и передаёт их студенту.

Остановка: `docker compose down` (данные сохраняются в volume `db-data`). Полное удаление данных: `docker compose down -v`.

## Режим разработки (SDK + БД в Docker)

1. БД:

   ```powershell
   copy .env.example .env   # если ещё нет; задайте POSTGRES_PASSWORD
   docker compose up -d db
   ```

   Postgres доступен на `localhost:5433` (только с локальной машины). Порт 5433 выбран, чтобы не конфликтовать с локально установленным PostgreSQL на 5432; меняется переменной `DB_PORT`.

2. Секреты API через user secrets (не попадают в репозиторий):

   ```powershell
   cd backend/src/MbaLms.Api
   dotnet user-secrets set "ConnectionStrings:Default" "Host=localhost;Port=5433;Database=mbalms;Username=mbalms;Password=<POSTGRES_PASSWORD из .env>"
   dotnet user-secrets set "Seed:ManagerEmail" "manager@example.com"
   dotnet user-secrets set "Seed:ManagerPassword" "<пароль менеджера>"
   cd ../../..
   ```

3. API (http://localhost:5001, Swagger UI: http://localhost:5001/swagger, OpenAPI: `/openapi/v1.json`):

   ```powershell
   dotnet run --project backend/src/MbaLms.Api --launch-profile http
   ```

   В Development миграции применяются при старте автоматически.

4. Frontend (http://localhost:5173, запросы `/api` проксируются на 5001; другой адрес задаётся `VITE_API_PROXY`):

   ```powershell
   cd frontend
   npm ci
   npm run dev
   ```

## Тесты и проверки

```powershell
dotnet test MbaLms.slnx          # требуется запущенный Docker: Testcontainers поднимает отдельный PostgreSQL
cd frontend
npm test                         # Vitest
npm run typecheck
npm run lint
```

Backend-тесты покрывают: аутентификацию и CSRF, ролевой доступ ко всем разделам, изоляцию данных студентов (расписание, оценки, опросы, уведомления), диапазон оценок 0–100 (границы 0 и 100, отказ для -1, 101 и дробных) и уникальность, публикацию оценок, ведомость (состав группы, сохранение только изменённых строк, чужие студенты, архивная группа), подтверждение и аудит изменения опубликованных оценок, недоступность черновиков студенту, жизненный цикл опросов обоих типов (черновик, редактирование, публикация, закрытие, повторное открытие), обязательность преподавателя и дисциплины для оценки преподавания, границы и подписи шкалы, период доступности (до начала, внутри, после окончания), валидацию ответов (обязательность, диапазон, чужие вопрос и вариант, вид значения, длина), один ответ на опрос (включая параллельную отправку), доступ только целевой группы (в том числе после перевода студента и архивирования группы), видимость автора менеджеру и закрытость чужих ответов от студентов, уведомления о публикации, права на все действия с опросами, выгрузку результатов (авторы, типы ячеек, защита от формул), архивирование и возврат групп, перевод студентов, полевую валидацию и уникальность названий, поиск и пагинацию студентов, переименование программы, расписание (все поля и статус, валидация времени, часовой пояс, видимость по группе, пересечения, права), уведомления (создание по трём событиям для каждого студента группы и только для неё, параметры и время, отсутствие уведомлений при сохранении без изменений, перенос занятия между группами, чтение только своих, 404 на чужое для студента и менеджера, `read-all` только своих, фильтр непрочитанных, 401 без входа), коды полевых ошибок вместо текстов ASP.NET, выгрузки Excel (структура OOXML, заголовки, кириллица, типы ячеек даты и времени, фильтры) и защиту от формул.

Frontend-тесты проверяют:

- **Локализацию:** совпадение ключей RU/EN, отсутствие пустых строк, одинаковые подстановки `{{…}}`, наличие каждого ключа из вызовов `t('…')` в коде, переводы всех кодов ошибок и полей из `Errors.cs` и всех значений перечислений из `Enums.cs`, текст для каждого типа и вида уведомления.
- **Язык:** русский по умолчанию, сохранение выбора и восстановление при следующем входе, `lang` у `<html>`, отказ от неизвестного значения.
- **Основные страницы менеджера и студента на английском:** нет русского текста интерфейса и сырых ключей.
- **Страницу уведомлений:** тексты RU/EN, ссылки, прочитанные и непрочитанные, «Прочитано», «Отметить все», счётчик в шапке.

Остальные: диалоги подтверждения (отмена не отправляет запрос), вывод серверной ошибки под полем, поиск и пагинацию таблиц, переименование программы, переключение на английский, форму занятия (время без смещения, статус, ошибка под полем окончания, предупреждение о пересечении), фильтры выгрузки расписания, отметку отменённых занятий у студента, ведомость оценок (0 и 100 сохраняются, -1/101/дробные блокируются до запроса, подтверждение изменения опубликованной оценки, публикация черновиков, серверная ошибка у строки студента, архивная группа только для чтения), подтверждение изменения опубликованной оценки на странице «Оценки», опросы (обязательные преподаватель и дисциплина только для оценки преподавания, подписи шкалы в запросе, ошибка сервера под полем, подтверждение публикации, закрытия и повторного открытия, подписи шкалы и обязательные вопросы у студента, отправка только значения нужного вида, сообщение о повторной отправке, после отправки — только свой статус и ответы, авторы и «ответили X из Y» у менеджера, выгрузка).


В production (`Database:MigrateOnStartup=false` по умолчанию вне Docker/Development) можно сгенерировать SQL-скрипт: `dotnet ef migrations script --idempotent --project backend/src/MbaLms.Api`.

## Часовой пояс

- Все моменты времени хранятся в UTC (`timestamptz`).
- Расписание и сроки опросов вводятся и показываются в часовом поясе программы `App:TimeZone` (по умолчанию `Europe/Moscow`, переменная `APP_TIMEZONE` в Docker) — независимо от часового пояса браузера пользователя. Это исключает расхождения у студентов, находящихся в других поясах.
- API принимает локальное время программы без смещения (`2026-10-06T10:00:00`) и отдаёт и UTC-значение, и локальное (`startsAtLocal`). Значение со смещением (`…Z`, `…+03:00`) отклоняется (`invalid`), а не пересчитывается молча. Несуществующее локальное время (переход на летнее время) тоже отклоняется.
- Фильтры по датам (`from`, `to`) — календарные дни в часовом поясе программы: занятие в 00:30 по Москве 10 марта попадает в 10 марта, хотя в UTC это ещё 9 марта.

## Резервное копирование и восстановление PostgreSQL

Бэкап (формат custom, сжатый):

```powershell
mkdir backups -Force
docker compose exec -T db pg_dump -U mbalms -d mbalms -Fc > backups/mbalms_2026-10-02.dump
```

> В Windows PowerShell 5 перенаправление `>` портит бинарные данные. Используйте PowerShell 7+, `cmd /c "docker compose exec -T db pg_dump -U mbalms -d mbalms -Fc > backups\mbalms.dump"` или дамп внутри контейнера:
> `docker compose exec db pg_dump -U mbalms -d mbalms -Fc -f /tmp/mbalms.dump` и `docker compose cp db:/tmp/mbalms.dump backups/mbalms.dump`.

Восстановление (заменяет текущие данные):

```powershell
docker compose stop api
docker compose cp backups/mbalms.dump db:/tmp/mbalms.dump
docker compose exec db pg_restore -U mbalms -d mbalms --clean --if-exists --no-owner /tmp/mbalms.dump
docker compose start api
```

Каталог `backups/` исключён из git. Дампы содержат персональные данные и пароли в виде хешей — храните их в защищённом месте. Ключи защиты данных ASP.NET (volume `api-keys`) нужны для действительности текущих сессий; при их потере пользователям достаточно войти заново.

## Безопасность

### Аутентификация

- ASP.NET Core Identity, без сторонних платформ. Пароли хранятся только хешами (PBKDF2), минимум 8 символов с заглавной, строчной буквой и цифрой.
- Блокировка учётной записи на 5 минут после 5 неудачных попыток; ограничение частоты запросов на вход (`RateLimiting:LoginPermitsPerMinute`, по умолчанию 20 в минуту с одного IP).
- Для несуществующего email и неверного пароля ответ одинаковый (`invalid_credentials`), время ответа выровнено — по входу нельзя узнать, зарегистрирован ли email.
- Начальный менеджер создаётся при старте из `Seed:ManagerEmail` / `Seed:ManagerPassword` (переменные `MANAGER_EMAIL` / `MANAGER_PASSWORD` в `.env` или user secrets), только если такой учётной записи ещё нет; существующая не изменяется. В коде и конфигурации репозитория паролей нет. После первого входа `MANAGER_PASSWORD` можно удалить.
- Студентов создаёт менеджер; сброс пароля студента менеджером и удаление студента завершают его активные сессии (проверка сессии раз в `Auth:SessionValidationInterval`, по умолчанию 1 минута).

### Сессия и CSRF

- Сессия — cookie `mbalms.auth`: `HttpOnly`, `SameSite=Strict`, срок 8 часов со скользящим продлением. Токенов в `localStorage` нет.
- Все изменяющие запросы, включая вход и выход, требуют CSRF-токен: клиент получает его в `GET /api/auth/csrf` и передаёт в заголовке `X-XSRF-TOKEN`.
- Флаг `Secure` для cookie: `Auth:CookieSecurePolicy` (`AUTH_COOKIE_SECURE_POLICY` в `.env`). `SameAsRequest` (по умолчанию) — для локального запуска по HTTP; **`Always` — для production за HTTPS**.

### Авторизация

- Запрет по умолчанию: любой endpoint требует входа, публичны только `GET /api/auth/csrf`, `POST /api/auth/login` и `GET /health`. Тест сверяет этот список со всеми зарегистрированными маршрутами.
- `/api/manager/*` — только роль Manager, `/api/student/*` — только роль Student (политики на сервере). Скрытие кнопок в интерфейсе защитой не является.
- Студент получает данные только по identity из сессии: идентификаторы студента, группы или пользователя из запроса не принимаются. Чужой опрос — 404, чужое уведомление — 404.

### Прочее
- Ошибки возвращаются в формате ProblemDetails с кодом ошибки, без stack trace. Пароли, токены и тексты ответов опросов не логируются.
- Выгрузки доступны только менеджеру; ячейки, начинающиеся с `=`, `+`, `-`, `@`, записываются как текст (защита от formula injection).
- Секреты задаются через `.env` (Docker) или user secrets (разработка); `.env` в git не попадает.
- Для production: разместите приложение за HTTPS-прокси и задайте `AUTH_COOKIE_SECURE_POLICY=Always`. В Docker API доступен только через nginx, поэтому включено доверие заголовкам `X-Forwarded-*` (`ForwardedHeaders:Enabled`); не публикуйте порт API наружу. Если TLS завершается на внешнем прокси перед nginx, передавайте его `X-Forwarded-Proto` дальше (в `nginx.conf` замените `$scheme` на `$http_x_forwarded_proto`). Ключи DataProtection хранятся в volume без шифрования — для MVP допустимо, для production рекомендуется ограничить доступ к volume или настроить шифрование ключей.
- Email-уведомления не отправляются (только в кабинете). Отправку можно добавить отдельно, не привязываясь к провайдеру: уведомления хранятся в БД и создаются через `NotificationService`.
